# Validation

`scripts/validate.py` is the single gate that decides whether a migrated job is correct. CI runs it
and reviewers expect its output pasted into every migration PR.

## Usage

Run from `datacloud-migration-demo/` (Python 3.10+, `pip install -r requirements.txt`, Java 17):

```bash
python scripts/validate.py payroll_join        # validate one job
python scripts/validate.py --all               # every job that has target/notebooks/nb_<job>.py
python scripts/validate.py --list              # migration status of every legacy job
python scripts/validate.py emp_metrics_daily -v --keep   # echo notebook logs, keep outputs for inspection
```

Exit code is `0` only if every requested job passes. Example (the exemplar):

```
=== payroll_join
[PASS] conformance: notebook + workflow follow MIGRATION_STANDARDS.md
[PASS] notebook ran on local PySpark in 6.1s (run_date=2024-03-15)
[PASS] payroll_join/payroll_by_cost_center.csv rows actual=25 expected=25
[PASS] payroll_join/payroll_by_employee.csv rows actual=29 expected=29

SUMMARY
  payroll_join         PASS
```

## What it does

1. **Conformance (static)** — `target/notebooks/nb_<job>.py`:
   `# Databricks notebook source` header and `# COMMAND ----------` cells; no Databricks-runtime-only
   imports (`pyspark.dbutils`, `databricks.*`, `dbruntime`, `delta`, `dlt`); no `SELECT *` /
   `.select("*")`; no ISO date literals outside widget defaults; required widgets `run_date`,
   `input_root`, `output_root`, `validate`; binds the `target.lib.dbutils_shim`; has a `--validate` cell
   calling `validation.compare_job`. `target/workflows/<job>.json`: valid JSON, `hr_daily.<job>` name,
   `job_clusters` with `spark_version` / `node_type_id` / `data_security_mode` / sizing, every task's
   `job_cluster_key` defined, a `notebook_task` pointing at `.../target/notebooks/nb_<job>` (no `.py`)
   passing `run_date`, `timeout_seconds` and `max_retries` on each task.
2. **Execution** — runs `python target/notebooks/nb_<job>.py --run_date=2024-03-15
   --input_root=legacy/sample_data --output_root=<fresh temp dir> --output_sink=csv` on local PySpark
   (`local[2]`, UTC, ANSI on). The validator writes to a scratch dir so stale files in
   `target/output/` can never produce a false pass.
3. **Golden diff** — for every `legacy/expected_outputs/<job>/*.csv`, compares the produced
   `<scratch>/<job>/<same name>.csv`.

## Comparison rule

**Exact match on sorted rows. No exceptions are currently documented.**

* Header row must be identical (same column names, same order).
* Data rows are parsed with Python's `csv` module and compared as a multiset of exact strings — row
  order does not matter, duplicates do, and `8.0` ≠ `8.00`, `" REG"` ≠ `"REG"`.
* A golden file with no produced counterpart fails (`missing actual output`); a produced CSV with no
  golden file fails (`unexpected output dataset`).
* On failure the report shows counts plus up to 10 sample rows that are missing from / unexpected in
  the output, which is usually enough to spot the rule (rounding, join type, as-of date) that drifted.

If a future job genuinely needs a looser rule (e.g. a float column), the rule must be added to
`target/lib/validation.py`, documented here *and* in `target/MIGRATION_STANDARDS.md` §7, in a
separate PR — never inside a migration PR.

## Where the golden outputs come from

`legacy/expected_outputs/` was produced by `scripts/seed/generate_expected_outputs.py`, a stdlib +
`Decimal` restatement of what the legacy Hive / Pig / Java / shell jobs compute on the March-2024
close, from the checked-in `legacy/sample_data/` (itself generated by
`scripts/seed/generate_sample_data.py`, seed `20240315`). Both scripts are deterministic; re-running
them produces no diff. Cross-checks performed when the goldens were cut:

| Job | Cross-checked against |
|---|---|
| `cohort_tagger` | `legacy/java/CohortTagger.java` compiled and run on the sample data — byte-identical after sort (CI re-checks) |
| `stage_and_publish` | `LOCAL_MODE=1 legacy/shell/stage_and_publish.sh stage 2024-03-15` audit file — identical (CI re-checks) |
| `payroll_join` | `target/notebooks/nb_payroll_join.py` on local PySpark — identical |
| `emp_metrics_daily`, `turnover_snapshot` | reference implementation only (no Hive runtime in this repo) |

The goldens are the contract. **Never edit them to make a migration pass.**

## Troubleshooting

* `Java gateway process exited` — install a JDK 11/17 and set `JAVA_HOME`.
* Spark binds to a weird interface / hangs at start — `export SPARK_LOCAL_IP=127.0.0.1` (the
  validator and `target/lib/spark.py` default it).
* `[FAIL] conformance: line N: hard-coded date literal` — derive the date from `run_date` with
  `target/lib/dates.py`, or expose it as a blank-by-default widget.
